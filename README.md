# Умный пешеходный переход — симуляция в CARLA

Симуляция участка для кейса «умный регулируемый переход»: T-перекрёсток в Town05, зебра через
дорогу 2+2. В мире ездят машины, ходят пешеходы, светофоры переключает наш скрипт.
Состояние участка (машины, пешеходы, фаза) уходит другу по WebSocket в JSON.

```
 CARLA-сервер ◄── run_scene.py (+ pedestrians.py)   крутит мир: светофоры, машины, пешеходы
      ▲
      └──────── ws_sender.py ──► ws://<ip>:8765 ──► друг   только читает мир и рассылает JSON
```

## Файлы

| файл | что делает |
|---|---|
| `run_scene.py` | **главная сцена.** Синхронный режим, фазы светофоров, поток машин, пешеходы, статистика в консоль |
| `pedestrians.py` | пешеходы на переходе. Подключается к `run_scene.py` сам. Отдельный запуск — только рисует геометрию |
| `ws_sender.py` | отдельный процесс: читает мир и рассылает JSON по WebSocket |
| `debug_view.py` | отладочное окно: вид сверху, машины с координатами, полосы, зоны. Мир не меняет |
| `camera.py` | две RGB-камеры (на зебру и на очередь машин): окно, ссылки на поток по HTTP, сохранение кадров для YOLO |
| `make_dataset.py` | синтетический датасет для YOLO: кадры с наших камер + автоматическая разметка, разная погода |
| `Dockerfile`, `docker-compose.yml` | сцена и отправщик в Docker одной командой (сервер CARLA — на хосте) |
| `.env.example` | все переменные окружения с значениями по умолчанию — образец для `.env` |
| `envconf.py` | чтение параметров из переменных окружения |
| `control.py` | канал «ползунки окна → сцена» (UDP, `127.0.0.1:8770`) |
| `JSON_FORMAT.md` | формат сообщений — это отправлять другу |
| `find_crossings.py` | поиск переходов на карте, загрузка карты (`--map Town05`) |
| `main.py` | разведчик: рисует светофоры, переходы и точки спавна у центра |
| `CLAUDE.md` | контекст проекта и все найденные грабли — читать, если что-то странное |

## Подготовка (один раз)

- CARLA 0.9.16 лежит в `~/simulator`, Python-окружение — `~/simulator/.venv` (в нём `carla==0.9.16`).
- Для отправки нужна `websockets`. В этом venv нет pip, ставится через uv:
  ```bash
  uv pip install --python ~/simulator/.venv/bin/python websockets
  ```

## Запуск

1. **Сервер CARLA** (отдельный терминал):
   ```bash
   ~/simulator/CarlaUE4.sh -quality-level=Low
   ```
2. **Карта Town05** — `run_scene.py` загрузит её сам, если открыта другая (переменная `CARLA_MAP`).
   Вручную, если нужно: `python find_crossings.py --map Town05` (сбрасывает мир).
3. **Сцена** (второй терминал):
   ```bash
   cd ~/carla_control && ~/simulator/.venv/bin/python run_scene.py
   ```
   Камера сама встанет над переходом. Дальше в окне CARLA камеру двигаешь мышью и WASD.
4. **Отправка другу** (третий терминал, после сцены):
   ```bash
   cd ~/carla_control && ~/simulator/.venv/bin/python ws_sender.py
   ```
   Друг подключается к `ws://<твой ip>:8765`. Свой ip: `hostname -I`.
   Порт 8765 должен быть открыт в фаерволе, если друг в другой сети.
5. **Остановка:** `Ctrl+C` **один раз** в терминале сцены. Скрипт сам уберёт машины и пешеходов
   и отпустит мир. `ws_sender.py` останавливается так же, мир он не трогает.

Проверить геометрию перехода без запуска сцены: `python pedestrians.py`. Скрипт на 60 с рисует
контур зебры (белый), торцы (красные), зоны ожидания W (зелёная) и E (синяя), точки появления людей.

## Запуск в Docker — одной командой

В контейнере только наши скрипты (сцена и отправщик). Сервер CARLA запускаешь на хосте, как обычно:

```bash
~/simulator/CarlaUE4.sh -quality-level=Low
```
```bash
cd ~/carla_control && docker compose up --build
```

- Сцена сама загрузит Town05, если открыта другая карта. Отправщик дождётся карты и начнёт слать
  JSON на `ws://<твой ip>:8765`.
- Контейнеры работают в сети хоста (`network_mode: host`, это Linux), поэтому порты 2000–2002 и 8765 те же, что без Docker.
- **Остановка — Ctrl+C один раз.** Compose отправит скриптам SIGINT, они уберут за собой.
  Второй Ctrl+C убивает контейнеры сразу, уборка не успеет, и мир «замёрзнет» (лечение — ниже).
- Отладочное окно — это GUI, его запускай на хосте, как обычно (`python debug_view.py`).
- Если Docker не установлен (Ubuntu), ставится так, потом перелогиниться:
  ```bash
  sudo apt install docker.io docker-compose-v2 && sudo usermod -aG docker $USER
  ```

### Управление переменными окружения

Любой параметр ниже задаётся либо в файле `.env` рядом с `docker-compose.yml`
(образец: `cp .env.example .env`, раскомментировать нужное), либо прямо в команде:

```bash
VEH_PER_HOUR=2000 PHASE_PED=25 DRAW_DEBUG=0 docker compose up
```

Без Docker работает точно так же: `VEH_PER_HOUR=2000 python run_scene.py`.
Не заданная или пустая переменная — значение по умолчанию. Кривое значение (например, `VEH_PER_HOUR=abc`) —
скрипт сразу остановится с понятной ошибкой.

| переменная | по умолчанию | что меняет |
|---|---|---|
| `CARLA_HOST`, `CARLA_PORT` | `localhost`, `2000` | где сервер CARLA |
| `CARLA_MAP` | `Town05` | какую карту загрузить сцене, если открыта другая; пусто — не трогать |
| `TM_PORT` | `8000` | порт Traffic Manager |
| `SEED` | `42` | зерно случайности |
| `VEH_PER_HOUR`, `MAX_VEHICLES` | `1200`, `60` | поток машин и потолок одновременно |
| `PHASE_MAIN`, `PHASE_SIDE`, `PHASE_PED` | `20`, `15`, `20` | длительности фаз, с (PED не меньше ~18) |
| `PED_PER_HOUR`, `MAX_PER_SIDE` | `360`, `3` | поток пешеходов и лимит живых с одной стороны |
| `PED_SPEED_MIN`, `PED_SPEED_MAX` | `1.2`, `1.6` | скорость пешеходов, м/с |
| `CROSS_MARGIN` | `2` | запас по времени на переход, с |
| `DRAW_DEBUG` | `1` | debug-отрисовка зон; `0` — при записи кадров для YOLO |
| `WS_HOST`, `WS_PORT` | `0.0.0.0`, `8765` | где слушает WebSocket |
| `SEND_PERIOD` | `0.5` | с симуляции между сообщениями |
| `ROAD_LENGTH` | `50` | м, докуда по нашей дороге считаем машины |
| `CONTROL_HOST`, `CONTROL_PORT` | `127.0.0.1`, `8770` | где сцена слушает ползунки окна (`0.0.0.0` — из сети) |

## Отладочное окно: координаты машин

```bash
cd ~/carla_control && ~/simulator/.venv/bin/python debug_view.py
```

Запускай при работающей сцене. Мир окно только читает, можно держать открытым вместе с `ws_sender.py`.

- **Слева карта сверху** (ориентация как у камеры в CARLA: +x вверх, +y вправо). Серые точки — полосы,
  белый контур — зебра, зелёный и синий квадраты — зоны ожидания W и E, жёлтая рамка — коридор
  нашей дороги. Машины в рамке попадают в JSON, у них жёлтая обводка и подпись `п3` — номер полосы.
  Цвет машины — тип: серый car, голубой van, оранжевый truck, жёлтый bus, красный special.
  Розовые точки — пешеходы.
- **Справа таблица** машин в радиусе 70 м: id, тип, **x, y**, полоса и направление, км/ч; ★ — машина в JSON.
- **Внизу** — координаты под курсором. Наведёшь на машину — её x, y, z и курс.
- **Клик** по карте печатает координаты точки (и машины под курсором) в консоль, оттуда их удобно копировать.
- Колесо мыши — масштаб, Esc — выход. `--screenshot файл.png` сохраняет картинку окна и выходит.
- **Ползунки справа внизу** меняют сцену на лету: машин в час, машин максимум, пешеходов в час,
  пешеходов на сторону. Тяни мышью (новое значение уходит, когда отпустишь) или крути колесом над ползунком.
  Сцена применяет изменение в течение секунды и пишет в консоль строку `> управление: ...`.
  Пока сцена не подтвердила значение, рядом написано, что в ней сейчас. Уже живые машины и люди
  доезжают и доходят свой путь: если убавить, станет меньше, но не сразу. `0` — новые не появляются.
  Если ползунки серые с надписью «сцена не отвечает», значит `run_scene.py` не запущен.
  Работает и со сценой в Docker. Пешеходов на сторону больше 3–4 лучше не ставить: в толпе они толкаются.

## Камера над перекрёстком

```bash
cd ~/carla_control && ~/simulator/.venv/bin/python camera.py
```

Запускай при работающей сцене. Скрипт ставит свои камеры, показывает картинки рядом в одном окне
(Esc — выход) и убирает камеры за собой. Сцену не трогает.

- **Камеры по умолчанию — две:**
  - `peds` — на зебру и пешеходов: северо-западный угол, 8 м, смотрит наискосок через зебру
    (`CAM_PEDS=21.94,-169.66,8.40,-50.7,-29.2`, точка снята свободной камерой в окне CARLA);
  - `cars` — на очередь у стоп-линии: 12 м перед зеброй со стороны главной дороги, 15 м, вдоль нашей
    дороги с наклоном −35° (`CAM_CARS=auto`).
- **Своя точка:** долети свободной камерой в окне CARLA, куда нужно, и выполни
  `camera.py --print-pose`. Он напечатает `CAM_POSE=x,y,z,yaw,pitch` и скажет, безопасна ли поза;
  камеру при этом не ставит. Позу можно задать в `CAM_PEDS`/`CAM_CARS` или поставить камеры списком:
  `CAM_POSE="x,y,z,yaw,pitch;x,y,z,yaw,pitch"`. `camera.py --from-spectator` ставит одну камеру
  прямо туда, куда смотрит свободная камера.
- **Ссылки для YOLO (как у IP-камеры).** Пока `camera.py` работает, камеры раздаются по HTTP на порту 8080.
  При старте скрипт печатает ссылки со своим адресом, в локальной сети это `192.168.0.16`:
  - `http://192.168.0.16:8080/` — страничка с обеими камерами, открыть в браузере для проверки;
  - `http://192.168.0.16:8080/peds.mjpg`, `.../cars.mjpg` — видеопоток (MJPEG, до 10 кадров/с);
  - `http://192.168.0.16:8080/peds.jpg`, `.../cars.jpg` — один последний кадр.

  YOLO открывает поток как обычную камеру:
  ```python
  from ultralytics import YOLO
  for r in YOLO("yolov8n.pt").predict(source="http://192.168.0.16:8080/peds.mjpg", stream=True):
      print(len(r.boxes))
  ```
  или `cv2.VideoCapture("http://192.168.0.16:8080/peds.mjpg")`. Без окна, только раздача: `camera.py --no-window`.
  Друг должен быть в той же сети, порт 8080 не закрыт фаерволом. Симуляция идёт быстрее реального времени,
  поэтому в потоке движение ускорено.
- **Кадры для YOLO на диск:** `camera.py --save frames/` сохраняет каждый кадр в jpg: `frames/peds/`, `frames/cars/`.
  В сцене при этом нужен `DRAW_DEBUG=0`, иначе в кадр попадёт отладочная отрисовка.
- **Не наклоняй камеру слабее ~30°, если она смотрит вдоль нашей дороги.** С горизонтом в кадре сервер
  CARLA падает (Signal 11). В другие стороны горизонт не мешает. Скрипт предупредит, если поза опасная.
- Параметры: `CAM_W`/`CAM_H` (1280×720), `CAM_FOV` (90°), `CAM_FPS` (10 кадров в секунду симуляции),
  `CAM_PEDS`, `CAM_CARS`, `CAM_BACK`, `CAM_SHIFT`, `CAM_HEIGHT`, `CAM_PITCH`, `CAM_POSE`;
  раздача — `CAM_HTTP_PORT` (8080, `0` — выключить), `CAM_HTTP_HOST`, `CAM_STREAM_FPS` (10), `CAM_JPEG_QUALITY` (85).

## Синтетический датасет для YOLO

```bash
cd ~/carla_control && DRAW_DEBUG=0 ~/simulator/.venv/bin/python run_scene.py
```
```bash
cd ~/carla_control && ~/simulator/.venv/bin/python make_dataset.py
```

Сцену обязательно запускай с `DRAW_DEBUG=0`, иначе отладочная отрисовка попадёт в кадры.

- **Как размечается.** В точку каждой нашей камеры (`peds`, `cars`) ставится пара сенсоров: RGB и
  instance segmentation. Второй знает для каждого пикселя, какой это объект, поэтому рамки получаются
  точно по видимой части людей и машин, без ручной разметки. Частично закрытые объекты тоже.
- **Классы — как в JSON:** `person`, `car`, `van`, `truck`, `bus`, `special`. Припаркованные машины-декорации
  (не акторы) — по классу из сегментации.
- **Разнообразие:** погода меняется блоками по кругу: ясно, облачно, мокро, дождь, закат, сильный дождь,
  ночь. В конце скрипт возвращает прежнюю погоду. Плотность потока можно крутить ползунками в `debug_view.py`
  прямо во время записи.
- **Результат** в `dataset/` (в git не попадает), формат ultralytics:
  `data.yaml`, `images/{train,val}/`, `labels/{train,val}/`, плюс `preview/` — первые кадры с нарисованными
  рамками, чтобы проверить разметку глазами. Разбивка train/val ≈ 80/20 кусками по 50 кадров, чтобы соседние
  почти одинаковые кадры не попали в обе части. Папку можно просто скопировать другу.
- **Обучение:** `yolo detect train data=dataset/data.yaml model=yolov8n.pt imgsz=1280`
- **Объём:** по умолчанию 2000 кадров, это ~7 минут и ~650 МБ. Меньше — `DS_IMAGES=300`.
- Параметры: `DS_IMAGES` (2000), `DS_OUT` (dataset), `DS_EVERY` (1 с симуляции), `DS_WEATHER_EVERY` (100),
  `DS_WEATHERS` (список пресетов через запятую), `DS_MIN_BOX` (6 px), `DS_EMPTY_SHARE` (0.1 — доля кадров
  без объектов), `DS_PREVIEW` (10). Позы камер — те же `CAM_PEDS`/`CAM_CARS`, что у `camera.py`.

## Что пишет сцена раз в секунду

```
[MAIN   12s] наш=Red  в зоне= 14  ждут у нас= 3  +57 -47 (не влезло 0)
   пеш: ждут W= 1 (макс  13с) E= 2 (макс   8с)  ср.ожид   9с (у перешедших 17с) | идут 2 переходят 0 уходят 1 | перешло 35 ...
```

- **Первая строка — машины:** фаза и секунда внутри неё, цвет нашего светофора, машин в зоне,
  сколько стоит у нашей стоп-линии, сколько появилось и удалено.
- **Вторая строка — пешеходы:** сколько ждёт с каждой стороны и дольше всех, среднее ожидание,
  сколько идёт, переходит и уходит, сколько всего перешло.
- **Строки с `!`** — проблемы: `застрял` (пешеход убран), `долгий переход`. Если их много, что-то не так.

## Как управлять — параметры

Всё настраивается константами в начале файлов. Поменял — перезапустил скрипт.

### `run_scene.py` — светофоры и машины

| параметр | сейчас | что меняет |
|---|---|---|
| `PHASES` | MAIN 20 / SIDE 15 / PED 20 с | цикл светофора: едет главная / едет наша дорога / всем машинам красный, идут пешеходы. **PED не делай меньше ~18 с**: пешеходы не успеют начать переход (переход 17–18 м) |
| `VEH_PER_HOUR` | 1200 | сколько машин в час появляется на всех подъездах |
| `MAX_VEHICLES` | 60 | потолок машин одновременно (бережём сервер) |
| `SOURCE_RING`, `SINK_RADIUS` | 40–150 м, 170 м | где появляются и где удаляются машины |
| `SEED` | 42 | зерно случайности. Тот же SEED — тот же поток |

Сейчас светофор работает **по таймеру**, на число машин и пешеходов не смотрит.

### `pedestrians.py` — пешеходы

| параметр | сейчас | что меняет |
|---|---|---|
| `PED_PER_HOUR` | 360 | сколько раз в час появляется пешеход (на обе стороны) |
| `MAX_PER_SIDE` | 3 | больше стольких живых людей с одной стороны не появится. **Сильно не поднимай**: в толпе люди сталкиваются и физика выбрасывает их на дорогу |
| `SPEED` | 1.2–1.6 м/с | скорость ходьбы |
| `CROSS_MARGIN` | 2 с | запас: человек начинает переход, только если до конца PED осталось не меньше путь/скорость + запас |
| `GROUP_PROB`, `GROUP_SIZE` | 0, 5–10 | группы. Выключены: 5–10 человек не влезают в лимит 3 на сторону |
| `DRAW_DEBUG` | `True` | debug-отрисовка в мире CARLA: контур зебры, торцы, точки ожидания W/E, точки появления людей. Держится, пока идёт сцена (перерисовывается раз в секунду). **Выключи, когда пишешь кадры для YOLO**, иначе отрисовка попадёт в кадр |

Остальные параметры — тонкая настройка ходьбы (обход соседей, бордюр, «застрял»). Их лучше не трогать.

### `ws_sender.py` — отправка

| параметр | сейчас | что меняет |
|---|---|---|
| `HOST`, `PORT` | `0.0.0.0`, 8765 | где слушает WebSocket. `0.0.0.0` — доступен из сети |
| `SEND_PERIOD` | 0.5 с | как часто слать, в секундах **симуляции**. Симуляция идёт быстрее реального времени, поэтому по часам сообщений больше |
| `ROAD_LENGTH` | 50 м | докуда по нашей дороге считаем машины |
| `ZONE_HALF` | 1.5 м | зона ожидания пешеходов — квадрат 3×3 м у бордюра |

## Если что-то сломалось

- **Мир «замёрз»** — скрипт убили жёстко или нажали Ctrl+C дважды, мир остался в синхронном режиме.
  Вернуть и убрать остатки:
  ```bash
  ~/simulator/.venv/bin/python -c "
  import carla; c = carla.Client('localhost', 2000); c.set_timeout(10); w = c.get_world()
  s = w.get_settings(); s.synchronous_mode = False; s.fixed_delta_seconds = None; w.apply_settings(s)
  left = list(w.get_actors().filter('walker.*')) + list(w.get_actors().filter('vehicle.*'))
  c.apply_batch_sync([carla.command.DestroyActor(a.id) for a in left]); w.freeze_all_traffic_lights(False)
  print('ok, убрано', len(left))"
  ```
- **Пересвет или глюк рендера** — перезапусти сервер с `-quality-level=Low`.
- **`ws_sender.py` пишет «Нет тиков мира»** — сервер CARLA не запущен или завис.
- **id светофоров поменялись** после перезапуска — это нормально, скрипты ищут всё по позиции.
- Остальные грабли (почему пешеходы ручные, бордюр, коллизии) — в `CLAUDE.md`.
